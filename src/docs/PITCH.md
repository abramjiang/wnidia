# 答辩口径与演示脚本

## 一、开场（30 秒）

> 「算力不缺，缺的是把已有算力用起来的调度层。WNIDIA 做三件事：
> 让 **Agent 用自然语言就能调算力**、让**不同厂商的芯片通过同一套接口被调度**、
> 让**每一次推理的结论都可以被复现和举证**。」

## 二、一句话定位

> **我们不是又一个 Agent 平台，而是 Agent 时代「可复现、可迁移、可调度」的私有推理底座。**

| 关键词 | 对应层次 | 现场证据 |
|---|---|---|
| 可复现 | 引擎层 | `engine-selector` 输出 `consistency_guarantee` 与 `consistency_satisfied`；TensorFold 可用 `draft:false` 逐字节对比自证 |
| 可迁移 | 硬件层 | 同一份 MLX-4bit 权重覆盖 Apple Metal 与 NVIDIA CUDA 两条内核路径；`/admin/engines` 展示后端矩阵 |
| 可调度 | 编排层 | 四档 tier（cloud/edge/home/cpu）+ 密级 L0–L4 + 抢占续算 + FinOps 计量 |

## 三、赛题对齐（Agent Skills 驱动的 Agent 应用）

本项目的 Agent 层就是「自然语言 → 选 Skill → 真实执行 → 中文回报」，
本次升级新增第 5 个 Skill：

| Skill | 一句话 |
|---|---|
| smart-dispatcher | 这个任务该发给谁，为什么 |
| gpu-slicer | 显存怎么切，开几个实例 |
| resource-doctor | 集群为什么利用率低 |
| idle-onboarding | 怎么把闲置设备纳管进来 |
| **engine-selector** ★ | **该用哪个推理引擎，能不能保证结论不变** |

## 四、演示脚本（8 分钟）

| 步骤 | 动作 | 看点 |
|---|---|---|
| 1 | 打开看板 `:8NN`，输入 Basic 账号 | 三节点在线，每节点显示 `engine` 与是否降级 |
| 2 | `GET /admin/compliance` | 一屏说清"我们怎么把红线写进代码"：仅 8888/9000 公网、凭据已脱敏、探测白名单 |
| 3 | Agent 输入「这个机密任务要求结论可举证，该用哪个推理引擎？」 | 真实调 `engine-selector`：L3 自动要求 exact 引擎，给出评分依据 + 降级链 + 一致性保证 |
| 4 | Agent 输入「这个高优实时任务该派给哪个节点？」 | `smart-dispatcher` 给出目标节点、评分与候选排名 |
| 5 | 注入抢占 `POST /admin/inject/preempt` | spot 任务存 checkpoint、高优任务接管、完成后**自动续算**（进度从被抢占处继续） |
| 6 | 注入掉线 `POST /admin/node/lost?node=cpu-1` | 隔离期内粘住不掉 → 在途任务重路由 → 隔离期结束后心跳恢复 |
| 7 | 打开作弊节点开关后发 `verify=true` 请求 | 三节点多数决识别异常节点并降信誉分（**确定性排序，可复现**） |
| 8 | `python skills/run_evals.py` | 32 条断言全绿，逐条打印 |

## 五、预判质询与回答

**Q：这不就是个调度器吗？K8s + Volcano 也能做。**
> 是，也不是。K8s 管容器，不管"这个任务该用哪个**引擎**、换了硬件结论还一样吗"。
> 我们的差异在引擎层：`engine-selector` 把「任务密级」直接映射成「必须逐字节可复现」的硬约束，
> 并且在无法满足时**明确标注未满足**，而不是悄悄换一个快一点但结果会漂移的引擎。

**Q：异构算力是不是只有一台机器在演？**
> 现在这一台就是三档的同构模拟——答辩材料里主动写明，不掩饰。
> 但"异构"这件事我们有两层真证据：① 引擎层的跨厂商后端（Metal ↔ CUDA 同一份权重）；
> ② 调度层已经预留 `home`（Mac/Jetson）与 `cpu` 档位，`idle-onboarding` 能直接把闲置设备纳管进来。
> 补一台 M 系列 Mac 就能当场跑出"真异构"的对照。

**Q：TensorFold 在你这里真的跑通了吗？**
> 目前是**登记在册、可选接入**，不是默认路径。原因我们也如实说：
> 它的 CUDA 路径官方只给 NGC 容器，而节点上没有 nvidia runtime（存在性检查写进了部署脚本，
> 检测不到会直接 `exit 2`）。所以我们不谎称"用了它"，而是把"引擎可插拔 + 可复现"做成了
> 可验证的机制，并在文档里写清接入的完整步骤与四个前置条件。

**Q：多数决会不会惩罚"措辞不同但意思一样"的诚实节点？**
> 不会。我们不直接用字符串相等，而是先走 JEV 语义判定（语义等价 + 证据支持 + 标签），
> 判定不可信时才回落到精确匹配；且**不足 3 个独立结果时不做任何信誉惩罚**。
> 另外本轮把 `majority()` 从 `max(set(...))`（平票时结果依集合迭代顺序而变）改成
> "先按出现次数、再按字典序"排序，保证同一批答案两次运行得到同一结论。

**Q：安全和合规怎么保证？**
> 默认拒绝。非回环绑定 + 弱口令会**直接拒绝启动**；只有 8888/9000 允许绑 `0.0.0.0`；
> 探测内网其他节点在发请求**之前**就被拦下；凭据在终端与日志里一律脱敏。
> `docs/COMPLIANCE.md` 是手册第八章逐条到代码的映射表，并附全仓出站连接清单供审计。

**Q：性能数据呢？**
> 本地 mock 证明了逻辑与韧性（见 `BENCHMARK.md` §2）；真机吞吐按 §3 的 before/after 口径采集，
> 未采集的格子我们保留【待真机填写】，不用估算值充当实测值。

## 六、必须主动说明的三件事（诚实分）

1. **三档 tier 目前由同一块 GB10 模拟**（单机伪分布式）；
2. **TensorFold 属"可接入未默认启用"**，原因是节点缺 nvidia runtime，且补齐属系统级变更需先报备；
3. **模型覆盖面窄**——TensorFold 只支持 3 个模型家族，这也是我们把"引擎可插拔"做成机制而非绑死单引擎的原因。

## 七、收尾（20 秒）

> 「所以我们交付的不是一个跑得快的模型，而是一层**可复现、可迁移、可调度**的算力底座：
> 换硬件不改代码，要举证能自证，闲下来的机器能入网。这也是我们把比赛用的这一台，
> 当成未来一百台来设计的原因。」
