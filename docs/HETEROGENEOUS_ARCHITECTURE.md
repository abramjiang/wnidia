---

## 1. 一句话定位

> **WNIDIA 不是"某种卡的调度器"，而是"跨架构中立的算力编排与计量层"。**
>
> 同一套 DeviceProfile + 路由 + 计量机制，同时纳管 CUDA 设备与 Apple Silicon 设备——
> 差异只体现在画像字段值上，不在调度逻辑里。

---

## 2. 三条赛道与边界

| 赛道 | 定位 | 竞争烈度 |
|---|---|---|
| **NVIDIA 全系列异构** | **主战场**（市场大、可复用） | 高 |
| **Mac ↔ NVIDIA 混编** | **楔子**（竞品少、痛点真） | 低 |
| AMD + 海外 NPU 异构 | 补充（避免供应商锁定） | 高 |

**明确不涉足**：国产算力卡（结构性理由见第 7 节）。

## 3. 三项核心机制（现状 → 升级）

> 现状结论基于对 r9 源码的**实读**，非推测。

### 3.1 DeviceProfile（设备画像）

| | 内容 |
|---|---|
| **r9 现状** | `NodeProfile` 已有容量/算力占比/代际/功耗/形态/可信度等字段，基础扎实 |
| **关键缺口** | ①**现有 `bandwidth_mbps` 是网络上行带宽，不是显存带宽**——核心维度缺失<br>②无 `precision_support`（决定量化）<br>③无 `memory_model`（unified vs discrete）<br>④无独立抽象 |
| **升级** | 新增 `DeviceProfile` 数据结构 + `DeviceRegistry`；**不替换** `NodeProfile`，渐进接入 |
| **状态** | ✅ **已实现**（14 项内置自检全过） |

### 3.2 画像路由

| | 内容 |
|---|---|
| **r9 现状** | `scheduler.score()` 已是多维路由：容量余量/负载/时延（可硬约束）/层级/声誉/密级/引擎健康，**工程完成度高** |
| **关键缺口** | 缺 TaskFeature（模型规模/上下文/并发/prefill-decode 倾向/隐私标签）；缺瓶颈维度（带宽/算力）；缺精度匹配 |
| **升级** | 硬约束**完全复用**，瓶颈打分作为 `score()` 附加项叠加，不重写 |
| **本质变化** | 从"哪个节点有空" → "**哪个节点最适合这类任务**" |

### 3.3 按画像计量

| | 内容 |
|---|---|
| **r9 现状** | `metering.py` 已实现 `meter_*(采数)` 与 `price_*(算钱)` **两层分离**，三种计价口径，并标记 `estimated`（真实 vs 估算） |
| **关键缺口** | 未按设备画像差异化计价；`power_w` 未入计价；无跨架构统一口径 |
| **升级** | 按 `family` 成本系数 + 能耗项；Mac 与 NVIDIA 统一以 token/任务数为基础度量 |
| **意义** | 统一口径是**混编可落地的真正前提**，也是 CSU 计量引擎的软件侧原型 |

## 4. 与两份开发文档的融合

| 机制 | 支撑 NVIDIA 全系列异构 | 支撑 Mac + NVIDIA 混编 |
|---|---|---|
| **DeviceProfile** | `family` 分层、`precision_support` 定量化、`interconnect` 定能否 TP | `memory_model=unified` 正确表达统一内存；`tags` 支撑隐私路由 |
| **路由** | 容量→高容量卡；带宽→高带宽卡；算力→高算力卡 | **本地优先 + 阈值兜底**；`privacy=True` 永不离开 Mac |
| **计量** | 反映不同代际/档次卡的成本差异 | Mac 与 NVIDIA **一张账单、可比成本** |

---

## 5. 工程约束（写死的设计原则）

1. **不做算子级异构并行** —— 跨卡 TP 受木桶效应与互联限制；采用**实例级异构路由**
2. **NVLink 有无决定并行策略** —— 有→可 TP；无→独立实例或 PP
3. **量化策略按探测结果定**，不写死
4. **新增硬件只注册画像，不改调度逻辑** —— 纳管 ≠ 适配
5. **渐进式迁移** —— 新结构补充而非替换，不破坏现有调度与计量

## 7. 关于不涉足国产算力卡（客观结构性理由）

| 维度 | NVIDIA 全系列 | 国产异构 |
|---|---|---|
| 适配成本 | **O(1)**（统一 CUDA 栈） | O(N)（N 家不兼容栈） |
| 复用率 | **高**（一次适配服务所有客户） | ≈0（客户被指定厂商绑定） |
| 价值主张 | **成立**（客户有选择自由） | **不成立**（无需选择自由） |
| 可规模化 | 产品化 | 退化为项目制 |
| 风险 | 低 | 合规/地缘风险高 |

**结论**：N 卡异构是"一次投入多次复用"的产品生意；
国产异构是"一次一适配"的项目生意，无规模效应。

> 对外口径：只做**商业结构性说明**，不否定国产算力的战略意义，
> 只说明"对 WNIDIA 这个具体产品不是合适的市场"。

## 8. 诚实边界（务必守住）

- 硬件参数需按官方 datasheet 复核，本文不固化未确认数值
- 成本系数为**占位设计**，须由真实采购/折旧/电价数据替换
- 路由权重需实测调优，初始值保守
- **WNIDIA 目前无付费客户**——本文为定位与设计，非需求验证
- DeviceProfile 已实现但**未接入调度**（M3 才消费），勿表述为"已生效"
- 计量目前无外部审计，若称"可信计量"需先解决认证问题
