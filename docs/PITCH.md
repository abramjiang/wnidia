## 四、第三幕：后端架构原理（5:00–7:00）

🖥️ 操作：切到架构图（README / ARCHITECTURE.md 的 Mermaid 图，或直接讲）。

🎙️ 台词（配合架构图，自上而下讲）：
> 前端之所以能"联动"，是因为后端是一套**闭环**。我带大家看后端到底发生了什么——一次推理进来的完整链路：

1. **接入层**：请求打到 API 网关 `:9000`，先鉴权。
2. **调度层**：调度器做云·边·端三级决策，调用「**引擎选择器**」——它会对 `TensorFold > vLLM > Ollama` 按负载、时延、代际**排名**，选最优落点。
3. **推理引擎层**：真实推理执行，演示环境跑的是 GX10 上的 **Ollama 0.33.2（GPU）**。
4. **JEV 可信校验层**：对结果做一致性裁决。
5. **计量层**：真实计时、真实计量，写入 `jev_log.jsonl`，可结算。
6. **边缘自治层**：断网/中断时，边缘 Agent 接管，恢复后回放。

> 〔强调创新〕和普通调度器的区别就在这三步：**异构代际感知**（不只是分派任务）、**边缘自治**（断网不停）、**可信计量闭环**（跑完能结算、能自证）。

🎙️ 诚实补充（建议主动说，避免被追问被动）：
> 这里我如实说明：推理和计量是**真机实测**；JEV 的"一致性裁决"在演示环境默认是 `mock` 模式——管道和指标都是真的，裁决结论用模拟保证可复现。生产环境一行配置 `WNIDIA_JEV_MODE=live` 就能切到**真实多模型裁决**。架构已经就绪，切换无损。

## 附录：Q&A 预案

**Q1：JEV 是真机校验吗？还是模拟的？**
> 如实答：推理与计量是真机实测（Ollama GPU 真跑、真实计时计量）；JEV 的"一致性裁决"在演示环境默认 `mock`，保证可复现，生产可切 `live` 真实多模型裁决。我们 BP 对照里也透明标注了这一点。

**Q2：和普通 K8s / 调度框架区别？**
> 答：三件事普通调度不做——异构代际感知（GPU/NPU/CPU 跨代际排名决策）、边缘自治（断网/中心云中断不罢工）、可信计量闭环（跑完能结算、能自证）。

**Q3：性能数据哪来的？可信吗？**
> 答：来自 GX10 节点上 Ollama 0.33.2 的真实推理，103 token / 24.4s / ¥0.0002 都是计量实测（`estimated=false`），并已落盘 `jev_log.jsonl`，可复查。

**Q4：断网真能跑？恢复不会丢吧？**
> 答：边缘 Agent 本地自治，断网任务不停；恢复后金色批次回放补记，账本 `+¥` 结算，分文不差——这是 r9 实测验证过的。

**Q5：部署难吗？**
> 答：一行命令 `bash scripts/deploy_gx10.sh`（GPU 模式）或 `MODE=preview` 本地预览，tmux 6 窗口自动拉起。详见 `docs/DEPLOY.md`。
